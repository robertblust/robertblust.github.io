# The home page — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** blust.ch's home page gains the vision with three checking tiles, the values with their "I never" line, and the newest post, every added word derived from the model or the blog index, bilingual.

**Architecture:** Two repositories in order. `robertblust/design` ships one minor: a `data-chat-open` hook in `chat.js`, anchors and a German option in the principles renderer, and a new `render/home` renderer. blust.ch re-pins it, adds a German file keyed on the model's exact English, renders the vision and values into the home page and /principles/ from it, copies the blog index's first entry into the home page, and holds all of it with `pages:check` and a `home` browser check.

**Tech Stack:** Node 22 ESM, `node:test`, Playwright (blust.ch `verify/check.mjs`), plain HTML/CSS, no bundler.

**Spec:** `docs/superpowers/specs/2026-09-27-homepage-design.md` (commit 0226cc7, branch `homepage-sections`).

## Global Constraints

- The headline, byline and first lede of `index.html` are unchanged, English and `data-de`, byte for byte.
- No call to action, no contact line, no talk named on the home page.
- No hand-typed count: the values heading's number word is written by the renderer from the model.
- The German of model strings lives in `build/principles.de.json` in blust.ch; the model stays English.
- German is made by the roles of `conventions/WRITING.md` (translator, editor, back-reader); the owner only picks among flagged alternatives. German is made after the owner has reviewed the English, never before.
- Nested markup inside a `data-de` value uses single quotes.
- en-US in all English, Swiss Standard German (ss, never ß; guillemets; spaced en-dash) in all German.
- Commits and PR bodies are in the git register: a prose subject, one to three paragraphs, a `Verified:` line, then `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`. PR bodies end with `🤖 Generated with [Claude Code](https://claude.com/claude-code)`.
- Commit only when the owner has said to execute this plan; open PRs and stop. Merging and tagging each wait for the owner's explicit word.
- Work in sibling worktrees: `~/git/robertblust/design-homepage-sections` and `~/git/robertblust/robertblust.github.io-homepage-sections`. Run `export PATH=/opt/homebrew/bin:$PATH` first in every shell.
- Refinement of the spec, §3: the German file stores each entry as `{ "en", "de" }` and is looked up by the exact English, rather than storing a SHA-256 of it. It fails in exactly the cases the spec names (English moved, English with no German) and the translator sees the source beside the German.

## Review Focus

- A value whose closing paragraph no longer begins "I never": the build must refuse with the value's id, never render another sentence. Pinned in Task D3.
- An entry in the German file that no English asks for any more (the model's English moved): `pages:check` must fail naming it, not leave dead German. Pinned in Task B2.
- A model string containing `&`, `<`, `"` or a backtick, in German inside `data-de`: must survive as text, not as markup or a broken attribute. Pinned in Task D2.
- A blog index whose first entry has a relative link: the home page must link `blog/<post>/`, not `<post>/`. Pinned in Task B5.
- A phone visitor: tiles and value rows stack, nothing scrolls sideways. Pinned in Task B7 and the existing `mobileNav`.

```js
// Renders the vision and the values into a site's home page from the artifact: the vision as
// the heading over the ways to check it, each value beside the line it will not cross.
//
// Derived for the reason /principles/ is: the home page is the surface most people read, and a
// hand-copied value is the first thing to drift. The page's own words — the kickers, the tiles,
// the heading's frame — stay the site's; the heading's number is written here from the model,
// because a count typed by hand goes stale without a sound.
import fs from "node:fs";
import path from "node:path";

import { valuesOf, slugOf, paragraphs } from "./principles.mjs";

const esc = (s) => s.replace(/&/g, "&amp;").replace(/</g, "&lt;").replace(/>/g, "&gt;");
const escAttr = (s) => s.replace(/&/g, "&amp;").replace(/"/g, "&quot;");

const WORDS = {
  en: ["", "", "Two", "Three", "Four", "Five", "Six", "Seven", "Eight", "Nine", "Ten", "Eleven", "Twelve"],
  de: ["", "", "Zwei", "Drei", "Vier", "Fünf", "Sechs", "Sieben", "Acht", "Neun", "Zehn", "Elf", "Zwölf"],
};

// The heading reads as a plural, so one value would need a sentence of its own; that is a
// decision for the day it happens, not a form to guess now.
export function numberWord(n, lang) {
  if (!(n >= 2 && n <= 12)) throw new Error(`the heading is written for between two and twelve values, and the model has ${n}`);
  return WORDS[lang][n];
}

// The line a value will not cross is its last paragraph, and it begins "I never". A value
// reworded so that it ends otherwise stops the build rather than put another sentence on the page.
export function neverOf(v) {
  const last = paragraphs(v.sections.at(-1).text).at(-1) || "";
  if (!last.startsWith("I never")) throw new Error(`${v.id}: its last paragraph does not begin "I never"`);
  return last;
}

// The name turns at its first comma: the clause after it is the accent.
function turned(name, escape) {
  const i = name.indexOf(",");
  if (i === -1) throw new Error(`the vision's name has no comma to turn at: ${name}`);
  return `${escape(name.slice(0, i + 1))} <em>${escape(name.slice(i + 1).trim())}</em>.`;
}

function vision(data, de) {
  const v = data.entities.find((e) => e.type === "vision");
  if (!v) throw new Error("the model holds no vision entity");
  return [
    `      <h2 data-de="${escAttr(turned(de(v.name), esc))}">${turned(v.name, esc)}</h2>`,
    `      <p class="lede" data-de="${escAttr(esc(de(v.tagline)))}">${esc(v.tagline)}</p>`,
  ].join("\n");
}

function values(data, de, heading) {
  const vs = valuesOf(data);
  const en = heading.en.replace("{n}", numberWord(vs.length, "en"));
  const hde = heading.de ? ` data-de="${escAttr(heading.de.replace("{n}", numberWord(vs.length, "de")))}"` : "";
  const out = [`      <h2${hde}>${en}</h2>`, `      <div class="values">`];
  for (const v of vs) {
    const never = neverOf(v);
```

```js
// The German of the model's words, held to the exact English it was made from. The model is
// written in English and stays so; this file is the site's translation of it. An entry is looked
// up by its English, so a sentence reworded in the model finds no German and stops the build, and
// the entry made for the old sentence is reported as unused rather than kept as dead German.
// The German is made by the roles of conventions/WRITING.md, never edited here by hand alone.
import fs from "node:fs";
import { valuesOf, paragraphs } from "@robertblust/design/render/principles";

export function loadGerman(file) {
  const entries = JSON.parse(fs.readFileSync(file, "utf8"));
  const map = new Map();
  for (const { en, de } of entries) {
    if (map.has(en)) throw new Error(`build/principles.de.json holds the English twice: "${en}"`);
    map.set(en, de);
  }
  const asked = new Set();
  return {
    de(en) {
      if (!map.has(en)) throw new Error(`no German for: "${en}" — add it to build/principles.de.json`);
      asked.add(en);
      return map.get(en);
    },
    unused: () => [...map.keys()].filter((en) => !asked.has(en)),
  };
}

// What the translator is given: every English string the home page and /principles/ translate.
export function strings(data) {
  const v = data.entities.find((e) => e.type === "vision");
  const out = [v.name, v.tagline];
  for (const s of v.sections.slice(0, 1)) out.push(s.heading, ...paragraphs(s.text));
  for (const x of valuesOf(data)) out.push(x.name, x.tagline, ...paragraphs(x.sections[0].text));
  return [...new Set(out)];
}
```

```js
// The home page's newest post is the blog index's first entry, copied rather than typed. A post
// is published by one edit, to the blog index, and this is what keeps that true: the home page
// is rewritten from the index, and pages:check fails while the two disagree.
import fs from "node:fs";
import path from "node:path";

const START = "<!-- latest:start -->";
const END = "<!-- latest:end -->";

export function writeLatest(_data, { check = false, root } = {}) {
  const blog = fs.readFileSync(path.join(root, "blog", "index.html"), "utf8");
  const m = /<a class="entry" href="([^"]+)">[\s\S]*?<\/a>/.exec(blog);
  if (!m) throw new Error("blog/index.html has no entry to put on the home page");
  const href = /^(https?:)?\/\//.test(m[1]) || m[1].startsWith("/") ? m[1] : `blog/${m[1]}`;
  const entry = m[0].replace(`href="${m[1]}"`, `href="${href}"`);
  const rel = "index.html";
  const file = path.join(root, rel);
  const page = fs.readFileSync(file, "utf8");
  const re = new RegExp(`${START}[\\s\\S]*?${END}`);
  if (!re.test(page)) throw new Error(`${rel} has no ${START} … ${END} block`);
  const next = page.replace(re, () => `${START}\n        ${entry}\n        ${END}`);
  if (next === page) return [];
  if (check) return [rel];
  fs.writeFileSync(file, next);
  return [];
```
