# The blog Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `/blog/` section on blust.ch, in the nav before Talks, listing posts on an index block the talks page shares, opening on one post that says why deciding well is solved for its author.

**Architecture:** The talks page's list rules move into the design package as a block, `index`, assembled into `page.css` like `principles`, `team` and `surfaces`, and the nav-order rule learns the label Blog; that is design v0.91.0. blust.ch re-pins it, adopts the block on `/talks/`, adds Blog to every nav, and gains `/blog/` and `/blog/deciding-well-solved/` as hand-written prose pages, bilingual through `data-de` and the German pipeline. Once the post is live, mental-model gains the post as a Community experience and the website surface names the blog.

**Tech Stack:** static HTML and CSS, the `@robertblust/design` package (node, `node --test`, Playwright in the site's verify), the site's `npm run design | og | sitemap | verify`, the vendored conventions roles for German, the meta-model's checks in mental-model.

**Spec:** `docs/superpowers/specs/2026-09-26-blog-design.md`

## Global Constraints

- Every repository lives in a sibling worktree named `<repo>-<branch>`; the clone stays on `main`. `export PATH=/opt/homebrew/bin:$PATH` before any `node`, `npm` or `gh`.
- Commits are prose in the git register: a plain subject under seventy characters, a short body saying what is now true, a `Verified:` line naming what was checked, then `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`. Never `git commit -m "feat: …"`. No headings or bullets in a commit or a pull-request body.
- Nothing is merged, tagged or released without Rob's explicit word for that step. A task that ends at a pull request stops there.
- The design package is American English in every file (`test/spelling.test.mjs`). The sites' prose is the register of `conventions/WRITING.md`: sentence case, American English, no serial comma, no adjective that sells.
- The post names no employer, no declined company, no school, no salary figure; every figure it carries stands in mental-model's `2026-career-break.md` or `2026-application-tooling.md`.
- Never edit `page.css`, `tokens.css` or any generated file in a site: `npm run design` overwrites it. A block changes in the design package and reaches a site by re-pin.
- The section is `Blog`, German `Blog`, URL `/blog/`; the post is `/blog/deciding-well-solved/`.
- Local servers: check `lsof -i :8000` before starting one; start only if the port is free, remember the PID, and stop only that PID.

## Review Focus

1. **The nav with eight items at 1280 px and at 640 px.** The `headerFits`, `headerBaseline` and `mobileNav` checks must pass on every page, since one more label can push the row to wrap. Pinned in Task 6 by running the site's verify on all pages after the nav edit.
2. **The `index` block's rules reaching other pages.** `page.css` is linked by every prose page, so a bare `.row`, `.t` or `.meta` would restyle the timeline or the ideas page. Pinned in Task 1 by a test that every selector in the block starts with `.index`, and in Task 5 by comparing computed styles on `/talks/` before and after.
3. **The German PDF swap on `/talks/`.** The `.dl` line's `data-de-href` must keep working after the class rename; the `translates.dlHref` check on `/talks/` pins it in Task 5.
4. **The post before its German exists.** CI runs `design german stale HEAD^1 HEAD` and the `translates` check; a page with English and no `data-de` must not fail the branch. Task 8 leaves the post without a `translates` entry until Task 9 adds the German and the entry.
5. **A new page's card and sitemap entry in CI.** `og:check` and `sitemap:check` fail on a page listed in verify but not in the recipe or the sitemap. Task 7 and Task 8 each add both and run both checks.

Each gets a `data-de` attribute whose value is its English for now: the tooling refuses an empty value, and the stale check compares base and head, not English against German. Inside the h1 the spans' double quotes become single quotes, the form the `/blog/` h1 uses.

```bash
node -e '
const fs=require("fs"); const f="blog/deciding-well-solved/index.html"; let h=fs.readFileSync(f,"utf8"); let n=0;
h=h.replace(/<(h1|h2|p)((?: class="[^"]*")? id="p\d+")>([^]*?)<\/\1>/g,(m,tag,attrs,inner)=>{ n++; const de=inner.replace(/"/g,"\x27").replace(/\n\s*/g," ").trim(); return `<${tag}${attrs} data-de="${de}">${inner}</${tag}>`; });
fs.writeFileSync(f,h); console.log(n,"elements")'
npx design german extract blog/deciding-well-solved/index.html | node -e "let s='';process.stdin.on('data',d=>s+=d).on('end',()=>console.log(Object.keys(JSON.parse(s)).length,'ids'))"
```

- [ ] **Step 2: Run the pipeline as four agents, one after the other**

For each page, `blog/index.html` (whose German was drafted in Task 7 and is reviewed here) and the post:

1. `npx design german extract <page> > /tmp/<name>-en.json`.
2. **Translator**: an agent given `conventions/TRANSLATOR.md`, `conventions/GERMAN.md`, `conventions/GLOSSARY.md` and the JSON, returning `{id: german}` for every id; it keeps good existing German.
3. `npx design german apply <page> /tmp/<name>-de.json`, then `npx design german german <page> > /tmp/<name>-de-only.json`.
4. **Editor**: an agent given `conventions/EDITOR.md`, `conventions/GERMAN.md` and the German-only JSON, never the English; returns corrected values and a list of flagged choices with alternatives.
5. **Back-reader**: an agent given `conventions/BACKREADER.md` and the edited German-only JSON; returns a literal English reading per id.
6. **Fidelity**: an agent given the English JSON and the back-reading; returns the ids whose meaning moved, with the German restored.
7. Apply the result with `npx design german apply`.
