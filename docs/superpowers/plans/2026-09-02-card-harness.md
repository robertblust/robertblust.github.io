# Card Harness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the four programs that render, stamp, check and test social cards into
`@robertblust/design`, taking the union of three drifted copies, without changing a single
card's bytes.

**Architecture:** Four zero-dependency modules under `cards/` in the package, each taking the
site's recipe module as its input. Each site keeps `og-recipe.mjs` — its card list, its frame,
its hide rules and its `REPO_ROOT` — and three thin callers. No fences, no generated bytes: a
visitor never downloads any of these files, so the governing rule makes every piece an import.

**Tech Stack:** Node 22+, ESM, `node:test` + `node:assert/strict`, Playwright (sites only —
the package never imports it).

**Spec:** [`docs/superpowers/specs/2026-09-02-card-harness-design.md`](../specs/2026-09-02-card-harness-design.md)

## Global Constraints

- **The package takes the union, never the intersection.** Every capability present in any of
  the three copies is present in the shared one. A consolidation that reduces what a site
  checks is a regression.
- **No `og.png` changes anywhere in this work.** `npm run og:check` is a fixed point on all
  three sites, before and after. Any card whose picture moves is a defect. **One expected
  exception, in Task 8 only:** dropping `from` from guestgraph's cards moves every guestgraph
  `og.sha`, because the recipe hashes every key of a card. Its diff must contain `og.sha`
  files and nothing else.
- **Zero dependencies and zero devDependencies in `@robertblust/design`.** It never imports
  Playwright — `exportCards` receives a `chromium`.
- **`cards/check.mjs` imports nothing outside node's standard library.** CI runs `og:check`
  before `npm ci`; a non-`node:` import there breaks the job's cheapest step.
- **`root` is never derived inside the package.** The site owns `REPO_ROOT` and passes it in.
  Deriving it from `import.meta.url` points inside `node_modules` — that is the `SITE_ROOT`
  defect from the suite runner round, and this plan avoids it by construction.
- **Every new gate is proven red by mutation before it is trusted.** A test that has never
  been seen to fail is not yet a gate. `Function.prototype.toString()` includes comments in
  the body, so a grep-for-a-token test can be defeated by a comment — assert behaviour.
- **Node 22+, ESM, `node:test` + `node:assert/strict`.**
- **Sites pin an exact tag**, never a commit SHA, never a `#semver:` range.
- **Merge with `gh pr merge --merge`, never `--squash`.** Author is
  `robert.blust@flatland.ch`. Stage by name; never `git add -A`.

## File Structure

**In `@robertblust/design` (new):**

| file | responsibility |
|---|---|
| `cards/recipe.mjs` | `sources`, `recipe`, `stampOf`, `state`, `stamp`, and `recipeFor(root)` which binds them |
| `cards/check.mjs` | `checkCards(recipeModule)` — staleness and dark-background, plus the PNG decoder |
| `cards/export.mjs` | `exportCards({ chromium, recipe })` — the union renderer |
| `cards/recipe-tests.mjs` | `checkRecipe(recipeModule)` — the 32 shared assertions |
| `test/cards-recipe.test.mjs` | tests for `cards/recipe.mjs` |
| `test/cards-check.test.mjs` | tests for `cards/check.mjs` |
| `test/cards-export.test.mjs` | tests for `cards/export.mjs`, against a fake browser |
| `test/cards-packaging.test.mjs` | every `cards/` module is reachable by its published specifier |

**In `@robertblust/design` (modified):** `package.json` — `files` gains `"cards"`, `exports`
gains four subpaths.

**In each site (modified):** `og-recipe.mjs` keeps its data and binds the machinery;
`export-og.mjs`, `og-check.mjs` and `verify/og-recipe.test.mjs` become thin callers;
`package.json` re-pins the tag.

## Interfaces

The whole design rests on one shape: **every package entry point takes the site's recipe
module.** That module is `og-recipe.mjs`, and it exports `cards`, `REPO_ROOT`, and the five
machinery functions bound to that root.

```js
// @robertblust/design/cards/recipe.mjs
export function sources(dir, root)           // -> string[], repository-relative, sorted
export function recipe(card, root)           // -> sha256 hex over knobs + source contents
export function stampOf(dir, root)           // -> absolute path of the og.sha beside a card
export function state(card, root)            // -> { dir, card, want, have, state }
export function stamp(card, root)            // -> void, writes the stamp
export function recipeFor(defaultRoot)       // -> the five above, with root defaulted

// @robertblust/design/cards/check.mjs
export function checkCards(recipeModule)     // -> number, count of problems

// @robertblust/design/cards/export.mjs
export async function exportCards({ chromium, recipe })   // recipe = the site's module

// @robertblust/design/cards/recipe-tests.mjs
export function checkRecipe(recipeModule)    // registers 32 node:test tests
```

`root` is **required** on the five raw functions and **defaulted** on what `recipeFor` returns.
Both forms must exist: the site's callers pass no root, and the shared test suite passes a
throwaway `tmp` root explicitly. A binder that swallowed the parameter would break every test
that builds a fake tree.

// test/cards-packaging.test.mjs
// A module under cards/ that is missing from `exports` or from `files` is invisible to a site,
// and the error names the package rather than the file. Both lists are hand-maintained, so
// both get a test rather than a habit.
import test from "node:test";
import assert from "node:assert/strict";
import fs from "node:fs";
import path from "node:path";

const pkg = JSON.parse(fs.readFileSync(new URL("../package.json", import.meta.url), "utf8"));
const dir = new URL("../cards/", import.meta.url);

test("every module under cards/ is published", () => {
  assert.ok(pkg.files.includes("cards"), "`files` must include cards/ or npm packs without it");
  for (const f of fs.readdirSync(dir)) {
    if (!f.endsWith(".mjs")) continue;
    const specifier = "./cards/" + path.basename(f, ".mjs");
    assert.equal(pkg.exports[specifier], "./cards/" + f,
      `${f} has no \`exports\` entry, so no site can import it`);
  }
});

test("every cards/ exports entry names a file that exists", () => {
  for (const [specifier, target] of Object.entries(pkg.exports)) {
    if (!specifier.startsWith("./cards/")) continue;
    assert.ok(fs.existsSync(new URL("../" + target, import.meta.url)),
      `${specifier} points at ${target}, which does not exist`);
  }
});

2. `page.addInitScript(() => { try { localStorage.setItem("rb-theme", "dark"); } catch (e) {} })`
   — all three. Pinned, not cleared: clearing inherits the boot script's default, which only
   looks like pinning while the default happens to be dark.
3. `page.emulateMedia({ reducedMotion: "reduce" })` when `c.settle === "reduced-motion"` —
   companygraph's. Pass it in `newPage` options as companygraph does, or via `emulateMedia`;

4. `goto(pathToFileURL(path.join(REPO_ROOT, c.dir, "index.html")).href + (c.hash || ""),

5. `await page.evaluate(() => document.fonts.ready)` — all three. A card rendered in the
   fallback face is a silent failure: nothing errors, and the type is not the type the page
   declares.
6. `if (c.hide) await page.addStyleTag({ content: c.hide })` — the guard is blust.ch's.
   Playwright rejects an empty style tag outright.
7. `if (c.titleSlide)` activate slide 0 — all three, identical.
8. settle: `reduced-motion` → nothing further (the emulation is the settle);
   `wait:<ms>` → `await page.waitForTimeout(<ms>)`. Default when `settle` is absent is
   `wait:900`, which is what blust.ch does today and is what keeps its cards byte-identical.
9. `page.screenshot({ path, clip: { x: 0, y: c.clipY, width: c.width, height: c.height } })`.
10. `stamp(c)` — **after** the screenshot, so a run that dies half way leaves the card
    reported stale rather than reported current on a file it never wrote.
11. `log("  ✓ " + path.relative(REPO_ROOT, out) + ` … `)`, then `page.close()`.

- [ ] **Step 2: Replace guestgraph's guard with schema validation**

Guestgraph today throws unless every card is `from: "file"` and `settle: "wait:900"`. Against
the union that asserts a limitation and would reject the capabilities this adds. Write instead:

```js
const KNOWN = new Set(["dir", "width", "height", "renderHeight", "deviceScaleFactor",
                       "clipY", "hide", "titleSlide", "settle", "hash"]);

// Guestgraph's exporter threw unless every card was file/wait:900. The intent is worth
// keeping and the assertion is not: og:check hashes the recipe, so a recipe describing a
// render the exporter does not perform is a stale card that reports itself current. What
// actually guarantees that is a fixed vocabulary — an unknown key is a knob that silently
// does nothing, which is the exact failure og:check exists to prevent.
function validate(cards) {
  for (const c of cards) {
    for (const k of Object.keys(c)) {
      if (!KNOWN.has(k)) throw new Error(`card ${c.dir}: unknown key "${k}"`);
    }
    for (const k of ["dir", "width", "height", "renderHeight", "clipY"]) {
      if (c[k] === undefined) throw new Error(`card ${c.dir}: missing "${k}"`);
    }
    if (c.settle !== undefined && !/^wait:\d+$|^reduced-motion$/.test(c.settle)) {
      throw new Error(`card ${c.dir}: settle "${c.settle}" is neither wait:<ms> nor reduced-motion`);
    }
  }
}
```

`from` is deliberately **not** in `KNOWN` — see spec decision 3. Guestgraph's recipe must drop
it in Task 8, and this validator is what will say so if it does not.

- [ ] **Step 3: Test against a fake browser, not Playwright**

  emulateMedia: (o) => calls.push(["media", o]),
  goto: (u) => calls.push(["goto", u]),
  evaluate: (f) => calls.push(["eval", String(f)]),

const fakeChromium = { launch: async () => ({ newPage: async (o) => (calls.push(["page", o]), fakePage), close: async () => {} }) };

- a card with `settle: "reduced-motion"` gets reduced-motion emulation and **no**
  `waitForTimeout`;
- a card with no `settle` gets `waitForTimeout(900)` and no emulation — *this is the test that
  keeps blust.ch's cards byte-identical*;
- a card with `hash: "#core"` has it appended to the URL;

- a card with no `hide` produces **no** `addStyleTag` call;

- `validate` rejects an unknown key, a missing `clipY`, and `settle: "wait"`;
- `validate` rejects `from: "file"`, so guestgraph's recipe cannot keep a field the exporter
